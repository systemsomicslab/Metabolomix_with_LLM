## 1. 目的

統計の計算を 1 つのエンジンにまとめ、対話のツール・spec の解析・概観・パスウェイのすべてがそれを通るようにする。
あわせて、レビュー（`docs/HISTRY.md` 2026-11-06）で見つかった統計の妥当性の問題を直す。

## 2. 目標・非目標・反目標

目標:

- 1 つのエンジン（analysis-spec を土台にする）。対話のツールは単純な引数から spec を組み立ててエンジンを呼び、
  使った spec を結果に保存する（対話の結果も `dataset_analysis_run` で同じ数字を出し直せる）。
- 前処理の順序（§4）、0 と欠測（§5）、検定の単位と検定（§6）、効果量と「変わっていない」の判定（§7）、
  多重性（§8）、交絡（§9）、PCA（§10）、組成（§11）を下に書くとおりにする。
- 結果に、どの定義で出た数字かを必ず書く（効果量の定義・検定・BH の母集団・前処理の recipe・入力の指紋）。

非目標:

- データの持ち方と定量の工程（B）。
- 概観の組み立て（A）。
- 再解析研究の手順書の書き換え（後で追従させる）。

反目標:

- 「有意でない」を「変わっていない」と表示する。
- 補完した値で検定する。gap-fill の値を、実測と区別できない形で検定や判定に使う。
- 反復注入を独立な試料として数える。
- 既存の spec（`analysis-spec.v1` など）が、この変更の後で黙って違う数字を出す（§12）。
- n が足りない群を黙って落として、指定と違う比較の答えを返す（v2 の既存の規則を保つ）。

## 4. 前処理

順序（品質管理の指針、Broadhurst ら 2018 Metabolomics 14:72 に沿う）:

1. **試料の選択**: `include`、役割（統計に使うのは Sample だけ。QC・Blank は品質の評価にだけ使う）。
2. **ドリフト補正**: 注入順に沿った QC の LOESS を**バッチごと**に当て、その後でバッチ間の水準を QC の中央値でそろえる。
   QC が試料の列に挟まっていない・少なすぎる・注入順が無いときは行わず、理由を書く（今の `_qc_interspersion` の検査を保つ）。
   LOESS の幅の決め方（交差検証など）は実装者に任せる。
3. **品質の足切り**（マスクはドリフト補正の後の値で計算し、まとめて当てる）:
   - ブランク比（生体試料の平均 / ブランクの平均）
   - 実検出率（gap-fill を数えない。B の `detected_mask`。群ごとの検出率で見るか全体で見るかは spec で指定）
   - QC の RSD（既定 0.30）
   - **D-ratio**（新規。QC の SD / 生体試料の SD。既定 0.5。私の判断）
4. **試料の正規化**（none / TIC / median / PQN）: 係数は、足切りで残った特徴だけから計算する。
   - B の内部標準で換算済みのデータでは、既定で掛けない。
   - 換算していないデータの既定は PQN（参照は QC の中央値、QC が無ければ試料の中央値。私の判断）。
5. **変換**: 有限の正値だけに log2 を当てる。0 以下は欠測にして理由を残す。pseudocount は足さない。
6. **反復のまとめ**: 同じ個体 ID（`subject_id`）の注入を、log の上で平均して 1 試料にする（§6）。
7. **補完**: 検定のためには行わない。PCA など完全な行列が要る計算にだけ行い、使ったことを結果に書く。

ドリフト補正の既定:

- 内部標準で換算していないデータでは、条件がそろえば行う。
- 内部標準で換算済みのデータで QC があるときは、既定を決めずに利用者に尋ねる（`needs_input` の封筒で、理由と選択肢を示す）。
  内部標準の比がドリフトの一部をすでに打ち消しているため。

前処理の結果は「行列」として名前（ID）を付けて登録し、解析は行列の ID を名指しする（今の v2 の `analysis_matrices` の考え方）。
前処理の記録は解析フォルダの `reports/` に書く（全体 §5）。

## 5. 0 と欠測：出方と量を分ける

- 試料ごとの値を「検出」「gap-fill」「欠測（0 を含む）」の 3 つに分けて持つ（B の `detected_mask` と値）。
- **出方の差**: 対比ごとに、群ごとの検出の例数と Fisher の正確検定。BH は出方の検定の中で別に掛ける。
- **量の差**: 値（検出と gap-fill）で検定する。欠測は欠測のまま（補完しない）。
- 片方の群で、実際に検出された試料（gap-fill でない）がその群の半数に満たない特徴は、量の検定の結果に
  「量の差は判定できない（出方の差を見る）」の印を付ける。判定（§7）は `inconclusive` にする。
  半数という閾値は spec で変えられる（既定 0.5。私の判断）。
- 今の `detection_driven` の考え方（検出の有無が差を作っているか）は、この印にまとめる。

## 6. 検定の単位と検定

- **検定の単位は生物学的な反復**（個体・抽出物）。試料の情報に `subject_id`（B の `dataset_set_sample_metadata`）を持たせる。
  同じ `subject_id` の注入は §4 の 6 で平均する。`subject_id` が無ければ各注入を 1 個体とみなし、その旨を結果に書く。
  反復注入らしい試料名（同じ名前の末尾の番号違いなど）を見つけたら、注意として知らせる（自動ではまとめない）。
- **既定の検定は moderated t**（limma 型の経験ベイズ。Smyth 2004）。log2 の上の線形モデルで、特徴をまたいで分散を借りる。
  - 2 群は群の 1 因子のモデル、3 群以上・2 因子は 1 つの線形モデルと対比（2×2 なら交互作用も問える）。
  - 「どれかの群で差があるか」は moderated F。
  - 同じ個体が両方の群にいる（対応のある）設計では、個体をブロックの因子としてモデルに入れる（私の判断）。
  - バッチなどの共変量をモデルに入れられる（§9）。
  - 欠測は特徴ごとに除いて当てはめる（残差の自由度が減る）。各群 2 個体未満なら、その特徴は検定しない（理由を書く）。
  - R の limma と同じ入力で同じ答えになることを、少なくとも 1 つの fixture で確かめる。期待値は一度だけ R で作って
    テストに保存し、作り方を文書に残す（limma は今の `r/` の環境に無い）。
- 選択肢: `welch`・`student`・`mannwhitney`（今の spec と同じ）。どれを使ったかを結果に書く。

## 7. 効果量と「変わっていない」の判定

- **log2FC の既定は、log の上の平均差（幾何平均比の log2）**。検定と同じ尺度。正なら比較群（test）が高い（今の向きの規約）。
- **効果量には必ず 95% 信頼区間を付ける**（moderated t ではモデルの SE と自由度から）。
- 算術平均比（`arithmetic_mean_ratio`）は spec で選べる（論文の再現のため）。そのときは区間を出さず、出さない理由を書く。
- 結果には必ず `effect_size_definition` を書く。
- **判定**（特徴 × 対比ごとに 1 つ）:
  - `changed`: BH の q が閾値（既定 0.05）以下。
  - `unchanged`: 効果量の 95% 信頼区間が、決めた幅（既定 ±20%、|log2FC| < log2(1.2) ≈ 0.263）に収まる。
  - `inconclusive`: どちらでもない（n が足りず判定できない、を含む）。§5 の印が付いた特徴もここ。
  - 幅と q の閾値は spec と対話のツールの引数で変えられる。
  - 95% の区間で判定するのは、同等性の検定（TOST）の有意水準 0.05 が使う 90% の区間より保守的（合意どおり 95% にする）。
- 大きさの閾値（今の volcano の |log2FC| ≥ 1）は、図の色分けと要約の数え方にだけ使い、判定には使わない（私の判断）。

## 8. 多重性

- BH の母集団の既定は、その解析で検定した全特徴（`matrix`）。結果に母集団の大きさを書く。
- `annotated`（同定された特徴だけ）は、spec で事前に宣言したときだけ使える。
- `reported`（論文が報告した特徴だけ）の q には `q_interpretation: reproduction_only` の印を付け、発見の FDR ではないと書く。
- 1 つの spec に名前付きの解析を並べたときは、`primary` を 1 つ宣言させ、残りもすべて結果に載せる（選んだものだけを出さない）。
- 出方の検定（§5）の BH は、量の検定とは別の母集団で掛ける。

## 9. 交絡

- 群 × バッチの対応表を、比較の結果に必ず付ける。
- 完全交絡（群とバッチを分けられない）は、今のとおり `allow_confounded=true` の明示なしには比較しない。
- 部分的な偏り（あるバッチに 1 群しか無い、など）は注意として知らせる。偏りの測り方（Cramér の V など）と閾値は実装者に任せる。
- 注入順と群の偏り（群ごとにまとめて測った、など）も知らせる。ドリフトが群の差に化けうるため（私の判断）。
- バッチは §6 のモデルに共変量として入れられる。バッチの情報が無いときは「評価できない」と書き、「交絡なし」と書かない（今の規則）。

## 10. PCA

- 前処理後の行列で、log2 と autoscale を既定にする（Pareto を選べる）。前処理前の行列では回さない。
- 軸は生体試料だけで決め、QC は同じ軸へ投影して重ねて描く（品質の確認。今の `fit_mask` を使う。私の判断）。
- 補完が要るときは §4 の 7 のとおり、使ったことを結果に書く。

## 11. 組成（クラスの割合）

- 「膜脂質の組成」のように、クラスの割合を比べる問いのための解析。
- 試料ごとにクラスの合計を作る（B の選別の後のデータ。分子種ごとに付加体は 1 つで、極性の重複は除かれている前提）。
- 割合のまま t 検定せず、**クラスの合計の CLR（中心化 log 比）**に §6 のエンジンを当てる。0 を含むクラスの扱い
  （除く・置き換える）は実装者に任せ、どうしたかを結果に書く。
- クラスの絶対量（例 pmol / 10^6 cells）の比較は、別の解析として並べて出す。
- クラスはオントロジー（MS-DIAL の Ontology）で決める。`assay_kind` が `lipid` のときは脂質クラスとして、
  それ以外のときは「MS-DIAL のオントロジー」として表示する（脂質名の文法を `lipid` 以外に当てない既存の規則）。

## 12. 既存の spec との互換

再解析研究は analysis-spec.v1・matrix-recipe.v2・claim-evidence-spec.v1・msms-rules.v1 で書いた spec を 96 本ほど持つ。

- これらの版の spec は、変更の後も同じ数字を出す（版ごとの意味を固定する）。既存の出力を使った回帰のテストで縛る
  （fixture はテスト自身が作る規約なので、合成の入力で v1 の数字を固定するテストを先に足してから作り変える）。
- 新しい既定（moderated t・95% の区間・判定・D-ratio・前処理の順序）は新しい版の spec（例 analysis-spec.v2）から効く。
- 対話のツールは新しい版だけを組み立てる。
- 「同じ数字」は、同じ入力の経路で読んだときの約束にする: 既存の spec を再現するときは `load_dataset(..., source="mztab")`
  （B §4.3）で読み、ライブラリは B §7.3 の規則（`msp_then_lbm` は MSP で全特徴を照合）で決まる。ツール名が変わる
  （`dataset_handle_open` → `load_dataset`）ので、再解析の手順書は呼び出しを書き換える（後で追従）。

## 13. 外部の契約

- 差次的結果の書き出し（`analysis/export_contract.py`、massbank-context との契約）の列は変えない。`log2fc` 列は今も
  log の上の平均差（v1 の `log_transform=True` の既定）なので、意味は変わらない（pseudocount をやめるので値は変わりうる）。
  効果量の定義・検定・判定の幅はメタ行として足す（massbank-context の `parse_differential` は知らないメタ行を読み飛ばすので、
  `CONTRACT_VERSION` は上げない）。列を足すときは版を上げて下流を同時に直す（既存の規則）。
- 根拠バンドル v3 の manifest にも同じ定義を足す。足す前に、massbank-context の `experiment/bundle.py` が知らない欄を
  許すかを確かめる。

## 14. ツール

- `dataset_preprocess`: §4 の行列を作り、行列の ID を返す。
- `dataset_compare`: 群（または対比）を受けて、既定の spec を組み立ててエンジンを呼ぶ。2 群・3 群以上・2 因子に対応する。
  戻り値は要約（判定ごとの件数・上位の特徴・交絡と品質の注意）。全量は結果の登録に置く（今の戻り値を細くする規則）。
- `dataset_pca`: §10。
- `dataset_analysis_run`: spec を受ける（今のツールの後継）。
- `pathway_project`: ノードの比較を §6 のエンジンで行う（BH はパスウェイ × スコープ種別ごとのまま）。

## 15. 実装者に任せること

- エンジンの内部の形（モジュールの分け方）。ただし入口は 1 つにし、v1 の `two_group_test` などを並べて残さない。
- LOESS の幅の決め方、部分的な交絡の測り方と閾値、CLR の 0 の扱い。
- spec の新しい版の欄の名前。
