## 1. 目的

このサーバは MS-DIAL の出力を LLM から扱えるようにする。今の作りには、同じことをする経路が並んでいる。

- ARF 経路と mzTab-M 経路が、前処理・PCA・差次的解析・書き出し・根拠バンドルの 5 組で並んでいる。
- 統計の計算が 3 世代ある（`dataset_differential` の v1、`dataset_statistic` の v2、`dataset_analysis_run` の analysis-spec）。
  さらに `arf_differential` とパスウェイ側の Welch がある。
- 統計の中身にも、科学的に直すべき点がある（0 と欠測、log2FC の定義、正規化の順序、ドリフト補正、交絡、小さい n）。

ツールは 91 個ある。Claude Code の過去の記録（1,177 回の呼び出し）を数えると、37 個は一度も呼ばれていない。
約 9 割は再解析研究（reanalysis-study）の呼び出しで、統計は `dataset_analysis_run` だけで回っている。
Claude Desktop の記録は手元に無く、数えていない。

### 1.1 利用者が目指すもの

- 解析ソフトは **MS-DIAL に固定**する（他のソフトの出力に広げることは目指さない）。
- 「汎用」とは**問いの立て方を問わず使えること**。
  - 問いを持ち込む使い方（主）: 例「群 A と群 B で膜脂質の組成がどう変わったか」。正しい統計の手続きで答える。
  - 問いを持たない使い方: データを開くと、データの特徴・言える事実・そこから考えられることを示す。
- データを開いた利用者が最初に知りたいのは「群の間で何が変わり、何が変わっていないか」。
- 最初の応答は粗くてよい。そこから**ツールを対話的に使って掘り下げられる**こと。
- 生データから、MS-DIAL Console でのアラインメント、キュレーションレビュー、付加体の選別、正規化、有意差の確認までを
  **すべて MCP の中で**行えること。

## 2. 目指す流れ

```
生データ ──(MS-DIAL Console、POS と NEG は別の実行)──┐
                                                      ├→ MS-DIAL の解析フォルダ（.arf / .arf2 / .dcl / .EIC.aef …）
GUI で解析済みのフォルダ ─────────────────────────┘
   → 読み込み（極性ごとに 1 つのデータセット）               … B
   → 最初の概観（暫定）                                       … A
   → キュレーションレビュー（人が判断する）                   … 既存の curation_*（B で DatasetState の上へ）
   → 極性ごとに内部標準で正規化（pmol / 10^6 cells）         … B（規則は msdial-workflow と共有）
   → POS と NEG の統合（試料を照合）                           … B
   → 付加体の選別・研究室の除外規則・内部標準の行を除く       … B
   → 前処理（ドリフト補正・品質の足切り・変換）               … C
   → 概観の出し直し → 問いに沿った比較・有意差               … A・C
```

- **入口は 2 つで、合流点は「MS-DIAL の解析フォルダ」**。Console の経路（D）はこのフォルダを作るところまで。
  その先は、どちらの入口から来ても同じ 1 本の鎖を通る。
- これまでの「主経路は GUI 解析済みの出力、Console は補助」（2026-10-06・10-07 の判断）は、
  **2 つの入口を対等に扱う**方針に改める。ENTRY POINT の「MS-DIAL を動かした形跡があれば下流へ、無ければ許可を取って
  Console を回す」は変えない。
- 鎖には人が判断する止まり場所がある（キュレーション、内部標準の候補の確認、試料の照合が食い違ったとき）。
  鎖は一気に自動で流さず、各工程の境目で止まり、続きから再開できる。工程の記録の形は §5。
- 工程の順番（正規化 → 統合 → 付加体の選別）は msdial-workflow と同じ。内部標準はそれぞれの極性の中で見つけるため。

## 4. 横断の決定

- **旧名は一度に切り替える**（移行期間を置かない）。`arf_*` などの旧ツール名は消す。Use-LLLM（すでに消えた名前を呼んでいて、
  本体と同期していない）と massbank-context の文書は、後から追従させる。この変更の中では両リポジトリを触らない。
- **文献検索と知識の蓄積は消す**（`paper_search`、`ingest_*` の 4 つ、`knowledge_coverage`、`log_search`、
  MCP リソースの `lipidmix://knowledge/*` と `lipidmix://playbook/*`、`knowledge/` `playbook/` の配信）。
  不足は massbank-context で補う。`write_report` は残す。
- **msdial-workflow の GUI は残す**。定量の規則（内部標準の対応と係数、付加体の採用表、除外規則、試料の照合）は
  1 か所に置き、GUI と MCP の両方がそれを使う（B §6）。
- **外部資産の場所は `lipidmix.local.toml` の 1 か所だけで指す**。資産の場所を上書きする環境変数を消す（B §7）。
- **データセットは自分を同定したライブラリを覚え、下流の照合は既定でそれを使う**（B §7）。
- 外部契約の旧名（環境変数の接頭辞 `LIPIDMIX_`、リソース URI `lipidmix://`、描画データの形式名 `lipidmix.<名前>.vN`、
  設定ファイル `lipidmix.local.toml`）は変えない（CLAUDE.md の規則どおり）。

## 5. 鎖の工程の記録

下流の鎖の各工程（キュレーション・正規化・統合・選別・前処理・解析）は、解析フォルダの `reports/` に記録を書く。

- 1 工程 1 記録。記録には、入力の指紋（元のファイルの sha256、前の工程の記録の ID）、設定、結果の要約、作った時刻を書く。
- 入力が変わると、それより後の工程の記録を「古い」と示す（消さない）。古い記録の結果は、新しい工程の入力に使わない。
- 条件を変えてやり直すときは、新しい記録を作る。元の記録は残す（msdial-workflow の「新しい run に分岐する」と同じ考え方）。
- 各工程は速いので、裏で動く worker は使わない。ツールの呼び出しがそのまま工程を進める。
- 記録の置き場所は解析フォルダの `reports/`（システム調整以外のデータ解析の記録はそこに置く既存の契約）。
  リポジトリ側には書かない。

記録のスキーマの細部（ファイル名・欄の名前）は実装者に任せる。決まっているのは上の性質と、次の 2 点（どちらも私の判断）。

- **再開はセッションとサーバの再起動をまたぐ。** ハンドルはメモリの中だけにあるので、`load_dataset` が解析フォルダの `reports/` に
  鎖の記録を見つけたら、古くなっていない最新の鎖を、記録した設定と人の選択（内部標準の `bindings`、試料の対応表、
  キュレーションの判断）から計算し直して戻す。戻したことと、戻した工程を状態の表示（A §3）に書く。
  `fresh=true` で記録を使わずに開ける。各工程の行列はファイルに残さない（計算し直しで足りる。決定論的であることを
  テストで縛る）。
- **POS と NEG を統合した後の記録の置き場所**: 2 つの解析フォルダの共通の親フォルダの `reports/`。共通の親が無い
  （別のドライブなど）・解析フォルダそのものが親子のときは、置き場所を利用者に尋ねる。統合前の工程の記録は、それぞれの
  極性の解析フォルダの `reports/` に置く。
- 概観の事実（A §8）も、この記録の 1 つとして残す。

## 6. 非目標

- MS-DIAL 以外の解析ソフト（MZmine・XCMS など）への対応。
- Use-LLLM・massbank-context・reanalysis-study の改修（この変更の後で追従させる）。
- msdial-workflow の GUI の作り直し（共有する規則を切り出すための変更だけを行う）。
- LBM（`.lbm2`）を使った下流での照合（B §7.3。後回し）。

## 7. 反目標（技術的に動いても失敗とみなすもの）

- 統計の結果が、どの定義（効果量・検定・BH の母集団・前処理）で出たかを結果から読み取れない。
- 「有意でない」を「変わっていない」として示す。
- 補完した値や gap-fill の値を、実測と区別できない形で検定や概観に使う。
- 同じ個体・抽出物からの反復注入を、独立な試料として数える。
- 再解析研究の既存の spec（analysis-spec.v1 など）が、この変更の後で黙って違う数字を出す（C §9）。
- 旧経路と新経路が並んだまま残る（切り替えの途中で止まる）。
