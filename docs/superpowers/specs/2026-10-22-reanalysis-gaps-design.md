## 1. 意図

ms-data-parser は、解析に必要な道具を一通り備えている前提で、**今回の再解析で足りなかった部分と問題があった部分だけ**を埋める。
目的は、再解析の判定の数字（統計と特徴の選び方）を、その場で書いたコードではなく、この道具の版のある、テスト済みの実装から
出せるようにすること（盲検の再解析の再現性）。

**守る条件（ユーザー決定 2026-10-22）**: LLM と対話しながら解析するという当初の目的を壊さない範囲だけ実装する。
- 既存の MCP のツールの振る舞い・戻り値・既定値を変えない。足すだけにする（戻り値を増やすときは opt-in の引数にする）。
- 主経路（GUI で解析済みの出力を読む）と、対話のセッション（`session_state`）の作りを変えない。新しい口は横に並べる。
- 新しいツールを MCP に足す場合も、既存のツールの件数・説明の整合（`test_server_registration.py`・`test_workflow_docs.py`）を保つ。

## 2. 確かめた事実（2026-10-22、main `a8dce5e`）

番号は §4 の項目と対応する。
1. **セッションが 1 つだけ**（`metabolomix/core/session_state.py:451` 付近）で、データセットとライブラリを 1 つずつしか持てない。
   並行の実行役が極性・データセットの違う処理を同時にすると衝突するので、reanalysis-study 側でラッパー（`msp_tools.py`）を書き、
   呼ぶたびに子プロセスを起こして `dataset_load` を毎回約 2.5 分やり直した。内部の関数（`session.library.last_match`、
   `_spot_query`、`alignment_spot`、`arf.reader.deserialize`）を直接呼んだ実行役も多い。
2. **`library_match_feature` の戻り値の TSV に、InChIKey・アラインメント・測定ピークが無い**（`metabolomix/library/tools.py:55-64`）。
   ライブラリを名前・分子式・InChIKey で引く口が無く、生の SQL を書いた（store を読み書きモードで開く: `store.py:443`）。
   `dcl_find_msms` は m/z で引くので、spot_id で代表スペクトルを引けない。
3. **`matched_peaks_count` が前駆体の一致も 1 本に数える**（`spectral_match.py:593`）。説明（`docs/output_format/library.md:32`）は
   「一致した参照ピークの本数」だけ。MTBLS3233 では、ある特徴の SME が実際には断片 0 本の一致だった。
4. **統計の種類が足りない**: 論文の方法に Student の t（log2 の上）＋算術平均の比の FC、Mann-Whitney、共変量（性・年齢・BMI）で
   調整した OLS が要った（reanalysis-study の `paper_stats.py`）。
5. **行列の作り方を論文に合わせられない**: 処理の順序が固定（補完が最後）、KNN は試料の方向・k≤5・NaN だけが対象、ドリフト補正は
   移動中央値だけ（`preprocessing.py:174-190, 358-385, 447`）、検出率のフィルタを役割（QC・生体試料）ごとに指定できない。
   「検出」に gap-fill を含めるかの定義も道具と再解析の側で違った（再解析は高さ>0、道具は実検出）。
6. **群の向きが分かりにくい**: 比較名は `RA_vs_HC` だが group_a=HC。統計の TSV の各行に群の名前が無い（mean_a・detected_a だけ。
   `feature_search.py:593, 808-812`）。実行役 3 人が log2FC の符号を取り違え、1 人の誤りは最後まで残った。
7. **MS/MS の合否と同族列の検査を毎回書いた**: 前駆体を除いた断片の本数、同じ分子式の別物との比較、脂質の頭部のクラス、診断イオン・
   中性損失（184.07、−141.02、PO3⁻/SO3⁻）の照会、同族列の RT の単調性（全実行役）。
8. **特徴どうしの関係**（同時溶出・付加体・同位体・源内断片）: `curation/relations.find_relations` はあるが、mzTab の任意の特徴には
   公開されていない。実行役が `coeluting()`・`insource_parents()` を書いた。
9. **細かい不具合**: (a) Bruker .d の中に baf2sql が `analysis.sqlite` を書くと、入力の指紋（`profiles.py:220` 付近）が変わり
   INPUT_CHANGED になる（reanalysis-study の issues.md 2026-10-20）。(b) メソッドファイルに ASCII 以外があると、計画の段階で
   `'ascii' codec` の例外になる（`method_file.py:624, 642`）。(c) m/z 帯ごとの質量精度（SME の ppm の分布）を出す口が無い。

## 3. 目標・非目標・反目標

目標:
- 再解析のエージェント（並行に複数）が、対話と同じ MCP のツールを、データセットのハンドルと spec で、互いに干渉せずに呼べる。
- 論文の方法（行列の作り方・検定・補正・閾値）と、特徴の選び方（付加体の層・許容幅・RT 窓・MS/MS の合否・同族列）を spec で表し、
  同じ spec なら同じ結果と同じ rule_hash が返る。
- オブザーバーの機械的な仕事（走らせ直しと照合、候補の網羅の走査）を、1 主張の「証拠の束」として道具が作る。

非目標:
- 論文の個体ごとの値（MAF など）との相関、論文の値の埋め値の確認（reanalysis-study の道具に置く）。
- 「明らかに別物」や override の発動の条件の判断（再解析の計画の規則で決める。道具は材料を返すだけ）。
- 主経路（GUI 出力の読み込み）や対話のセッションの作り替え。
- Console・pipeline の経路の大きな改修（§2 の 9 の不具合を直すだけ）。

反目標:
- 既存の MCP のツールの戻り値・既定値・説明が変わる。
- spec に無い暗黙の既定で結果が変わる（spec を正規化して rule_hash に入れ、既定値も埋めて返す）。
- `dataset_handle` を渡した呼び出しが、対話のセッションの 1 つの状態（ハンドルを渡さない呼び出しが使う状態）を読み書きする。

## 4. 作るもの（優先度順）

1. **MCP のツールが状態を引数で受け取れる（データセットとライブラリのハンドル）**（ユーザー決定 2026-10-22: 再解析のエージェントも
   対話と同じ MCP のツールを使う。CLI の別の入口は作らない）。
   - Workflow のエージェントは親のセッションの MCP サーバ（1 つのプロセス）を共有する。いまのサーバはデータセットとライブラリを
     1 つずつのグローバルな状態に持つので、並行のエージェントが別の極性・データセットを扱うと上書きし合い、`last_match` のような
     「直前の呼び出しの状態」に依存する戻り値は競合する。
   - そこで、1 つのサーバがデータセット（とその極性のライブラリ）を**ハンドル（ID）で複数持てる**ようにする。読み込みのツール
     （`dataset_load` など）はハンドルを返し、`dataset_*`・`library_*`・`dcl_*`・新しいツールは**省略可能な引数 `dataset_handle`**
     （と必要なら `polarity`）を受ける。引数を渡さなければ、今までどおり既存のセッションの 1 つの状態で動く（対話の使い方は変わらない）。
   - 結果が前の呼び出しの状態に依存しないようにする（照合の詳細は `last_match` から読ませず、戻り値で返す。§4 の 2）。
   - 同じ入力（指紋が同じ）の読み込みは、ハンドルを使い回してよい。ハンドルの寿命と上限（メモリ）を決める。
   - 大きな結果（証拠の束、感度解析の並び）は、指定したパスへ JSON を書き、要約だけを返す形を選べる（文脈を膨らませない）。
   - 1 つのサーバのプロセスに重い呼び出し（数分かかる読み込み）が並行で来たとき、ほかの呼び出しを止めないか（イベントループを
     塞がないか）を確かめ、塞ぐなら重い処理をスレッドかプロセスへ逃がす。
   - 呼び出しの引数（spec）はエージェントのトランスクリプトに残る。結果の JSON にも正規化した spec と rule_hash を書く。
   以下の 2〜8・10・11 は、MCP のツール（既存のツールへの opt-in の引数か、新しいツール）として呼べるようにする。テストのために、
   同じ処理を Python の関数としても呼べる形にしてよい。
2. **照合の戻り値と、ライブラリの読み取り専用の検索**: `library_match_feature` に opt-in の引数で、InChIKey、アラインメント、
   測定ピーク、`fragment_matches_excl_precursor`（前駆体 ±許容幅を除いた断片の一致の本数）を返す。spot_id で代表スペクトルを引く。
   ライブラリを名前・分子式・InChIKey の先頭ブロックで引く（store は読み取り専用で開く）。`matched_peaks_count` の説明に前駆体の
   扱いを明記する（値の意味は変えない）。
3. **統計の種類**: `student_log2`（log2 の上の Student の t、FC は算術平均の比）・`mannwhitney`・`ols_covariates`。補正（BH・なし）、
   閾値（p・q・FC）、BH の母集団を spec に持たせ、結果に写す。
   - **共変量**は spec から別の TSV（試料名と共変量の列）を指す。既存の実験情報シート（sample-manifest）の契約は変えない。カテゴリの
     符号化と欠測の扱い（欠測のある例を除くか）も spec に持たせ、rule_hash に入れる。
   - **感度解析を 1 つの spec に並べられる**: 行列の作り方の違う複数の解析（例: 前処理なし、半最小値の補完、Welch、Mann-Whitney、
     共変量の調整）を名前つきで並べ、それぞれの数字（統計量・p・q・FC・群平均）と向きを返す。再現したかどうかの判定は返さない
     （判定は再解析の側の取りまとめが行う）。
4. **行列の recipe**: 処理の順序（`order`）、特徴の方向の KNN（`k`・欠測の定義 `zero|nan`）、LOESS のドリフト補正（`span`）、
   役割ごとの検出率（QC・生体試料）、`detection_basis`（`detected` = 実検出だけ / `positive` = 高さ>0、gap-fill を含む）、
   半最小値の補完、前処理なし。既存の recipe の既定は変えない。
   - **KNN と LOESS は標準の定義に合わせる**（R の `impute::impute.knn` 相当、statsmodels の `lowess`）。その場の実装には合わせない。
     参照（関数と版）を `docs/output_format/` に書く。statsmodels を依存に足してよい（依存の変え方はこのリポジトリの作法どおり）。
5. **群の向き**: 統計の結果の各行に `group_a`・`group_b` の名前を入れ、比較名（`<test>_vs_<ref>`）と同じ向きの
   `log2fc_test_over_ref` を足す。既存の欄は残す。
6. **MS/MS の合否と同族列の検査**: `msms_qualify`（規則: 前駆体を除いた断片の最小本数、上位何位までを見るか、同じ分子式の別物との
   差、脂質の頭部のクラス、診断イオン・中性損失の一覧）と、同族列の RT の単調性の検査（同族の生成規則と許す外れ）。どちらも規則を
   正規化して rule_hash を返す。診断イオンの照会（spot_id と m/z の一覧と許容幅）も足す。
7. **特徴どうしの関係**: mzTab の任意の特徴について、同時溶出の特徴、付加体・同位体・源内断片の関係（`relations` を流用）を返す。
8. **証拠の束**: 1 主張（目標の物質・spec）について、候補の網羅の走査（付加体・許容幅を広げた走査を含む）、各候補の照合と
   `msms_qualify`、関係、**規則で選んだ既定の特徴**（`dataset_feature_search` の目標照合と同じ規則。決まらなければ `needs_input`）を、
   1 つの JSON にまとめて返す。spec の rule_hash と入力の指紋を含める。同じ spec で走らせ直せば同じ JSON になる（オブザーバーの
   「走らせ直しと照合」は、この JSON の一致で済む）。
   - 特徴を最終的に決めるのは再解析の実行役（override の規則の範囲）で、道具は決めない。決めた特徴での統計は 3・4 を別に呼ぶ
     （統計の spec が feature_id を外から受け取る）。
9. **細かい不具合**: (a) 入力の指紋から .d の中の `analysis.sqlite`（baf2sql のキャッシュ）を除く。(b) メソッドファイルの ASCII を
   計画の前に検査し、行と文字を示す分かりやすいエラーにする。(c) m/z 帯ごとの質量精度（SME の ppm の分布）を返す口。
10. **外部の行列を受ける口**: 3・4 の統計が、mzTab-M・pipeline の run に加えて、外部の行列（試料 × 特徴の TSV と、試料と群の対応）を
    入力に取れる。再解析の較正（論文自身の個体ごとの値＝MAF・mwTab に論文の検定を当てる）に使い、検定の実装を 1 つに保つ。
11. **主の判定のための数字**: クラスの主張（クラスに注釈された特徴の高さを試料ごとに足して検定。足した特徴の一覧も返す）、
    比の主張（2 つの特徴の個体ごとの比を検定）、新しい知見の候補の一覧（SME・許容幅・q の閾値・除く対象を spec で受ける）。

**ライブラリの指定**: spec には極性だけを書き、研究室の参照ライブラリの実体は設定ファイル（`lipidmix.local.toml` の
`[library] msp_positive` / `msp_negative`）から引く（`library_mode=msp_only` と同じ規則）。結果にはファイル名と sha256 だけを残し、
パスを書かない（再解析の側は spec をコミットするので、パスを追跡対象に書けない）。

## 5. 受け入れの条件

- 既存のテストがすべて通り、既存の MCP のツールの戻り値が変わらない（足した opt-in の引数を渡さない限り）。
- 1〜8 のそれぞれに、テスト（fixture はテスト自身が作る）がある。同じ spec で 2 回呼んで結果と rule_hash が一致するテストを含む。
- 1 つのサーバで、別々の極性のデータセットを 2 つのハンドルで持ち、並行に呼んでも互いに影響しない（テスト）。`dataset_handle` を
  渡さない呼び出しは、変更前と同じ結果になる（テスト）。
- 3・4 は、reanalysis-study の MTBLS3233 の二次解析で使われた方法（PQN・KNN（特徴の方向）・LOESS・Student の t（log2）・BH）を
  spec で表し、その場のコードの結果（`runs/MTBLS3233/results/paper_method/`）と数字が一致するか、違いを説明できること
  （この確認は reanalysis-study の側で行ってよい）。
- `docs/output_format/` と `docs/workflow/`、USAGE.md、CLAUDE.md の規模表記を更新する。
