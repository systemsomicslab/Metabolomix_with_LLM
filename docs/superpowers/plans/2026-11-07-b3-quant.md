# B-3 定量の工程（msdial-workflow と共有） Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** msdial-workflow の定量の規則（内部標準の正規化・試料の照合・付加体の選別と除外）を入出力から切り離した純粋な関数として切り出し、ms-data-parser がそれを**任意のプラグイン**として読み込んで `DatasetState` の上に 4 つの工程ツールを載せる。

**Architecture:** 規則は msdial-workflow リポジトリ内のパッケージ `msdial_rules`（`packages/msdial-rules/src/msdial_rules/`、標準ライブラリだけ）に置き、GUI/CLI はそれを直接 import する。MCP 向けには辞書だけでやり取りする薄い面 `msdial_rules.api`（`API_VERSION = 1`）を持つ。ms-data-parser は**依存として宣言しない**: `lipidmix.local.toml` の `[quant] rules` がそのパッケージのフォルダを指していればそこから読み込み、無ければ 4 ツールが「未設定」の封筒を返す。ms-data-parser 側で公開するのは、設定の書式とプラグインの面の仕様（`docs/quant-rules-plugin.md`）だけ。新しいパッケージ `metabolomix/quant/` に、プラグインの読み込み・`DatasetState` → 規則の入力への変換・工程の記録（解析フォルダの `reports/quant/`）・派生データセットのハンドル登録・4 ツールを置く。正規化済みのデータセットには `DatasetState.quant_state` で「正規化済み・方法・単位」を持たせ、C の前処理がそれを読む。

**Tech Stack:** Python 3.13+/3.14、hatchling（msdial-workflow）、importlib（プラグインの読み込み）、numpy、FastMCP、pytest。

> **2026-11-07 利用者の判断（spec §6.1 の「commit を固定した git 依存」を置き換える）**: 規則はプラグインのような扱いにし、任意の設定にする。ms-data-parser 側で公開するのは設定の書式だけ。したがって `pyproject.toml`・`uv.lock`・`requirements*.lock.txt` には何も足さず、公開リポジトリの利用者は認証の問題に出会わない。gap-fill は「計算して印を付ける」（推奨どおり）。

## Global Constraints

- 規則は msdial-workflow 側に純粋な関数として置く（spec §6.1）。ms-data-parser は依存として宣言せず、`[quant] rules` で指されたときだけ読み込む（利用者の判断 2026-11-07）。`pyproject.toml`・`uv.lock`・`requirements*.lock.txt` を変えない。ローカルのパスは追跡対象に書かない（`lipidmix.example.toml` には架空のパスの例だけ）。
- 規則が未設定でも、ほかのツールと全テストはそのまま動く。4 ツールは `quant_rules_unavailable` の封筒（設定の書き方を書く）を返す。
- 研究室の参照 CSV（内部標準の係数・付加体の採用表）・provenance・参照ライブラリの**場所と中身**を、追跡対象の文書・テスト・戻り値に書かない。戻り値は参照表の sha256・単位・ファイル名の末尾だけ。データセットに現れたクラスについてだけ、使った内部標準と係数を示す（spec §6.1・§6.2 の 1、§2 反目標）。

## 規則プラグイン

**msdial-workflow 側の形.** `packages/msdial-rules/src/msdial_rules/` に標準ライブラリだけのパッケージを置く。
- パッケージ内の import はすべて相対 import にする（どのフォルダから読み込まれても動くように）。
- msdial-workflow 本体の wheel の `packages` に加える。editable install と配布 zip（`git ls-files` 由来）にもそのまま入るので、**GUI の配布物を入れた機械は、そのフォルダを指すだけで MCP からも同じ規則が使える**。
- MCP 向けの面は `msdial_rules.api`。引数と戻り値は辞書・list・str・float・None だけで、ms-data-parser は msdial_rules の型を知らない。

```python
API_VERSION = 1
RULES_VERSION: str          # 規則の版（クラス別名・除外規則・パッケージの版を合わせたもの）

def normalize(features: list[dict], n_samples: int, reference_text: str,
              method: str = "cell_coefficient", bindings: dict[str, int] | None = None) -> dict
    # features[i]: {feature_id:int, name, lipid_class, mz, rt, adduct, heights:[float|None], detected:[bool]}
    # -> {unit, normalization_method, values:[[float|None]], statuses:[[str]], roles:[str],
    #     assignments:{target_class: {standard_name, feature_id, coefficient, concentration,
    #                  standard_adduct, unit, status, candidates:[{feature_id,name,adduct,mz,rt}]}},
    #     any_others_classes:[str], fallback_by_feature:[bool]}
def coefficient_reference_text(reference_text: str, concentrations: dict[str, float],
                               solvent_volume: float, cells_millions: float, unit: str | None = None) -> str
def match_samples(names_by_mode: dict[str, list[str]], mapping_rows: list[dict] | None = None) -> dict
    # -> {rule, ids_by_mode:{mode:[共通 ID（元の順）]}, mismatched:{mode:[ID]}, rows_by_mode:{mode:{元の名前: 対応表の行}}|None}
def select(features: list[dict], adduct_text: str | None) -> list[dict]
    # features[i]: {feature_id:str, name, comment, msms_assigned:"True"|"False", ontology, adduct, mode, role}
    # -> [{feature_id, action, reason, original_class, canonical_class, adduct, mode, class_rule_version}]
```
- 規則が入力を拒むときは `ValueError` の派生（`.code` と `.details` を持つ）を投げる。ms-data-parser は `.code` を読んで `QUANT_RULES_REJECTED` の封筒に包む。

**ms-data-parser 側の形.**
- `lipidmix.local.toml`:
  ```toml
  [quant]
  rules = "C:/path/to/msdial-workflow/packages/msdial-rules/src/msdial_rules"   # パッケージのフォルダ
  adducts = "C:/path/to/adduct-selection.csv"                                   # 付加体の採用表
  ```
  どちらもパスとして解く（`user_config`）。環境変数は作らない。
- `metabolomix/quant/plugin.py` がそのフォルダを `importlib.util.spec_from_file_location("msdial_rules", <folder>/__init__.py, submodule_search_locations=[folder])` で読み込み、`msdial_rules.api` を返す。
  - `API_VERSION != 1` なら `quant_rules_incompatible` の封筒。
  - 読み込んだ規則の `RULES_VERSION` と**中身の指紋**（パッケージの `*.py` を名前順に連結した sha256）を、各工程の記録の `settings.rules` に書く。
  - 記録から計算し直すとき、指紋が違えばその工程から先を「古い」として戻さない（規則の版を固定する代わりに、記録が使った版を縛る）。
- 公開する文書は `docs/quant-rules-plugin.md`。内容は設定の書式・上の面の仕様・記録に残るもので、研究室の表の中身や場所は書かない。

**認証.** ms-data-parser の取得とセットアップには関わらない（宣言していないので）。規則を使う研究室の各機は、次のどちらかでフォルダを手元に置き、`[quant] rules` で指す:
- msdial-workflow の GUI の配布 zip を展開する
- 非公開リポジトリを clone する（その機の利用者にアクセス権が要る）

`server_update` は ms-data-parser だけを更新する。規則の更新は GUI の配布物か clone の更新で行い、記録の指紋で「どの版で計算したか」が残る。

**テスト.** ms-data-parser のテストは、`tests/quant_fake_rules.py` が tmp に書き出す小さな偽のプラグイン（`api` の 4 関数を、表で決めた単純な規則で実装）を `[quant] rules` に向けて使う。本物との同値性（spec §10）は、pytest の任意のオプション `--quant-rules=<フォルダ>` を渡したときだけ走る `tests/test_quant_parity.py` で確かめる（既定では skip。本物の規則は msdial-workflow 側のテストが縛る）。

## Review Focus

- **POS/NEG の試料が名前だけでは揃わない**（`pos` を含む名前と含まない名前の混在、片方にしか無い試料）: 黙って部分集合で統合せず、照合の規則と食い違う試料を挙げて止まる。対応表で進められる。→ Task 12 の `test_merge_stops_on_mismatched_samples`。
- **同じ極性のデータセットを 2 つ渡す・正規化の状態が違う 2 つを渡す**（片方だけ正規化済み、単位違い）: 統合しない。→ Task 12 の `test_merge_refuses_same_polarity_and_mixed_units`。
- **正規化済みのデータセットに、もう一度正規化を掛ける**: 二重の割り算を黙って作らない。→ Task 11 の `test_apply_refuses_already_normalized`。
- **キュレーションの判断を付けた後でデータセットを開き直す・`.arf2` が変わる**（記録の指紋が古い）: 古い記録の結果を使わず、古いと示す。→ Task 5 の `test_stale_when_source_sha_changes`、Task 14 の `test_restore_skips_stale_chain`。
- **極性が決められないデータセット**（`ion_mode_majority` が `None`、ハンドルにも極性が無い）: 付加体の選別キーと統合の ID 接頭辞に要るので、推測せず `polarity` 引数を求めて止まる。→ Task 6 の `test_polarity_required_when_unknown`。
